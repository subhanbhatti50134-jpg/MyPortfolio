# License decision — MyPortfolio

This repository (a personal developer portfolio) does **not** yet carry an
open-source license. Until a license is added, all rights are reserved by
default and the code, images, and CV cannot legally be reused or distributed
by others.

## Context

A portfolio's main value is to **show your work to employers and
collaborators**, not to be reused as-is by others. You therefore have two
reasonable paths:

### Option A — Keep it "All Rights Reserved" (no LICENSE file)
- You retain full control over your portfolio code, design, and CV.
- Others can read it on GitHub but cannot legally copy or reuse it.
- Appropriate if you want to protect your personal branding and résumé content.

### Option B — Add a permissive license (MIT recommended)
- Lets others learn from and reuse your code structure/components.
- MIT is short, clear, and carries a warranty disclaimer.
- Good if you want your portfolio code to be useful to other developers.

## Recommendation

For a personal portfolio, **Option A (no license)** is perfectly reasonable
and common: the goal is to present *your* work, not to distribute it. If you
want other developers to freely reuse your UI components, add an MIT `LICENSE`
file instead.

## How to adopt (if choosing MIT)

1. Add a `LICENSE` file at the repository root with the MIT license text
   (from opensource.org/licenses/mit).

3. Keep this `LICENSE_DECISION.md` as a record of the decision.
